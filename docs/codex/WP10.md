# WP10 — Live topology, room-level presence, roaming trail & sticky clients

Read `docs/codex/BRIEF.md`, `docs/PLAN-infra.md`, `docs/unifi-wire-shapes-infra.md`, `shared/schemas/infra.ts`
(Topology*, Room*, RoamEvent, ClientRoams, StickyClient), and the WP8/WP9 code you build on. Endpoints marked
`WP10` in `shared/api.ts` are in scope, plus rule trigger `person.room_entered/left`, condition `person.room`,
action `client.kick`, and `PATCH /api/devices/:mac` (room assignment).

## 1. Topology (`server/engine/infra/topology.ts` — pure builder + thin endpoint)
Inputs: normalised devices (WP8), port views (WP9: speeds, caps, PoE, issues), active clients, people,
egresses with health (`inventory.listEgresses()`), WAN rates (`server/unifi/wan.ts`).
- **Root = gateway** device node `dev:<mac>` (`parentId: null`). There is no `internet` node in this WP (the
  kind stays in the enum for later).
- **Egress nodes** `egress:<id>` (`kind:'egress'`, `egressId`, state from health: healthy→ok, degraded→warning,
  down→down), `parentId` = gateway node; edge medium `wan` (WAN: speed/rates from the gateway WAN uplink data)
  or `vpn` (VPN client: rates null unless known). The UI draws them to the **left** of the gateway.
- **Device nodes**: parent = `dev:<uplink.mac>`; unknown uplink → parent gateway with `speedMbps:null` and
  no bottleneck. Edge: `parentPort` (uplink_remote_port), `childPort` (uplink.port_idx), speed/duplex,
  `maxSpeedMbps` = min(parent port caps, child uplink port caps when known), `downBps` (towards child = parent
  port tx rate, else child uplink rx) / `upBps`, `utilizationPct` = max(down,up)/speed, `signal` for mesh
  (`medium:'wireless'`), `poeW` = PoE power of the parent port when it powers the child.
- **Client groups**: per AP one `clients:<apMac>` node (wireless members); per switch/gateway port with wired
  clients that are not adopted devices one `clients:<switchMac>:<port>` node. `members` = `TopologyClient`
  (name = Unifire display name, personId, signal, rates). `people` = distinct personIds. Edge medium
  wire/wireless, rates = sum of members, `parentPort` for wired groups.
- Node `clients` = direct clients (devices) / member count (groups); `people` for device nodes = union of their
  client groups; `poeW` for switches = used PoE; `state`: offline→down, any warning/error issue→warning, else ok.
- **Bottlenecks** (`bottlenecks[]` + edge `bottlenecks`, i18n `topology.bottleneck.<kind>` with params
  `{parent, child, speed, max, util, signal}`): `speed_below_capability` (negotiated < maxSpeedMbps),
  `high_utilization` (≥ 80 % in the latest poll), `weak_mesh` (signal < −70 dBm), `half_duplex`, `errors`
  (parent port has an `errors` issue). Child devices of a bottleneck edge get the device issue `bottleneck`.
- `GET /api/topology`; live `topology {ts}` after devices/clients cache changes, throttled ≤ 1 / 10 s.

## 2. Rooms (`server/engine/infra/rooms.ts`)
- Tables `rooms` (id, name, floor, icon, color, order), `ap_rooms` (apMac PK → roomId), `room_segments`
  (id, personId, roomId nullable, apMac, start, end). `infra_devices.roomId` must mirror `ap_rooms` (single
  source: `ap_rooms`; `PATCH /api/devices/:mac {roomId}` and `PUT /api/rooms/assign` both write it).
  Deleting a room unassigns its APs and closes its open segments.
- Room presence runs inside the existing per-minute presence update (`server/engine/presence.ts`): for each
  person who is home, among their online presence devices that are wireless, take the one with the strongest
  signal → its `ap_mac` → room (null if the AP has no room). **Dwell hysteresis**: the candidate must stay the
  same for `settings.rooms.dwellMinutes` consecutive minutes before the segment changes (keeps phones that
  ping-pong between APs from flapping). Leaving home closes the open segment.
- Events: `person.room_left {personId, roomId}` then `person.room_entered {personId, roomId}`; live `room`;
  rule triggers with personId/roomId filters; condition `person.room {personId, roomId, inRoom}`;
  notify/webhook placeholders `{{room}}`, `{{person}}` (useful for Home Assistant webhooks).
- API: rooms CRUD, `PUT /api/rooms/assign`, `GET /api/presence/rooms?from&to` (`RoomTimeline`, includes
  `current` per person), `Room.occupants`. Retention for `room_segments` 1 year.

## 3. Roaming trail (`server/engine/infra/roaming.ts`)
- Network 11 sends **no `EVT_WU_Roam` frames** (capture). Detect roams from `ap_mac` changes: (a) WS
  `sta:sync` client docs (already parsed into `client.updated` events — compare with the cached ap_mac), and (b)
  the per-minute active-client poll as fallback. Dedupe: same mac + same destination AP within 90 s = one event
  (keep the earliest ts; source `ws` wins). Record `fromSignal` (last known on the old AP), `toSignal`, `band`
  (radio ng/na/6e → 2.4/5/6), `channel`. Table `client_roams`, retention 90 days.
- Per-minute RF samples for wireless clients `client_rf_minutes` (mac, ts, apMac, signal), retention 7 days.
- `GET /api/clients/:mac/roams?from&to` → `ClientRoams` (events, `apDwell` minutes per AP from RF samples,
  `signal` series 1-min, max 24 h of points — downsample beyond that). `InfraDeviceDetail.roams24h` for APs.

## 4. Sticky clients
`settings.sticky`: a wireless client with signal ≤ `signalDbm` for ≥ `minutes` consecutive minutes on the
same AP while ≥ 1 other online AP broadcasts the same SSID (from device `vap_table`/WLAN data) → status
`sticky`. Recovery: signal > threshold + 5 dB, or a roam → `recovered` (keep 1 h, then drop). Persist in
`sticky_flags`. **Nudge** (only if `settings.sticky.nudge`): kick-sta through the existing write gate
(`client.kick`, audit category `client`, actor system, dry-run honoured), only if the client's current rate
< `skipAboveBps`, ≤ `maxNudgesPerDay` per client, ≥ 30 min between nudges, never for blocked/paused clients.
Status `nudged` after a nudge. `GET /api/roaming/sticky`. Rule action `client.kick` uses the same path.
