# UniFi Network API reference for Nuxt 4 and Nitro

**Research cutoff: 2026-11-26.** Ubiquiti’s release feed lists **Network 11.0.104 as Official**, **11.1.58 as Release Candidate**, and **10.6.109 as Official** on the 10.x branch, with **10.6.111 as Release Candidate**. The public Network API portal resolved to **11.0.97 documentation** during this research. Its HTTP API namespace is still **`/integration/v1`**. This report uses that published schema for the endpoint inventory and labels private behavior separately. The JSON examples use synthetic values. I did not run requests against a controller. [Release feed](https://community.ui.com/releases/) · [10.6.109 release](https://community.ui.com/releases/UniFi-Network-Application-10-6-109/772020d5-1426-4015-bbd6-631d28803933) · [11.0.104 release](https://community.ui.com/releases/UniFi-Network-Application-11-0-104/f6136744-4cf3-460d-93a6-c5328a89ab22) · [Developer portal](https://developer.ui.com/network/v11.0.97/gettingstarted)

**Confidence** — **High** means vendor documentation or a published schema explicitly covers the claim. **Medium** means implementation source, fixtures, or a reported controller observation supports it, with build or hardware variation possible. **Low** means the exact wire behavior or portability remains unverified. Confidence applies to the item as stated, including any version limits.

**Recommendation:** build a thin server-side Integration API client and a separate local session adapter. Use the Integration API for inventory, device restart, PoE power-cycle, vouchers, and supported configuration. Put policy-based route control behind the session adapter and qualify egress changes against each supported controller build. UniFi already offers native guest quotas, device auto-recovery, and scheduling in the Policy Engine’s Object Manager. The strongest reasons to build the app are custom per-device WAN/VPN switching, quota and approval workflows for ordinary clients, and configuration diffs. [Integration API schema](https://opastorello.github.io/unifi-api-docs/network/v11.0.97/index.html) · [Policy Engine](https://help.ui.com/hc/en-us/articles/5546542486551-Traffic-Policy-Management-in-UniFi) · [Hotspot quotas](https://help.ui.com/hc/en-us/articles/115000166827-UniFi-Hotspots-and-Captive-Portals) · [Device Supervisor](https://community.ui.com/releases/3ed8145b-94a2-44b2-a42e-2d970f135b7b?replyId=4f40ee39-88d9-4cd3-aaff-271042e3796b)

## 1. Official Network Integration and Site Manager APIs

### Network Integration API

On a UniFi OS console, send `X-API-KEY` to `https://<console>/proxy/network/integration/v1`. For local access, generate the key in **Network → Integrations**. Ubiquiti directs integrators to that screen for the documentation matching the installed build. Use `GET /sites` to resolve the site UUID and `internalReference`. A paginated collection typically returns `offset`, `limit`, `count`, `totalCount`, and `data`. Filter syntax and valid fields are operation-specific. **High.** [Ubiquiti API setup](https://help.ui.com/hc/en-us/articles/30076656117655-Getting-Started-with-the-Official-UniFi-API) · [Published OpenAPI snapshot](https://raw.githubusercontent.com/enuno/unifi-mcp-server/main/scripts/scraped-api-spec-v11.0.97.json) · [Filtering](https://developer.ui.com/network/v10.3.58/filtering)

This is the full resource inventory in the **11.0.97** schema. Paths are relative to `/proxy/network/integration/v1`. `S` means `/sites/{siteId}` and `/{id}` means the item under the collection on that row. Every row has **High** confidence for the published schema. [Vendor portal](https://developer.ui.com/network/v11.0.97/gettingstarted) · [OpenAPI operation inventory](https://opastorello.github.io/unifi-api-docs/network/v11.0.97/index.html)

The schema also lacks historical client usage, measured DPI counters, the Network WebSocket, and a speed-test action. ### Site Manager and Cloud Connector

Site Manager v1.0 uses `https://api.ui.com` and a key created in **Site Manager → Settings → API Keys**. The account-level API is read-only, including the `POST` ISP query. The separate Cloud Connector can forward supported application writes. Ubiquiti documents **10,000 requests/minute for Site Manager v1**, **100/minute for Early Access**, and `429` with `Retry-After`. The Connector has its own **100/minute per console**, **25-second timeout**, and **10 MB upstream response limit**. Its docs specify console firmware **5.0.3+** and distinguish owner keys from organization keys. **High.** [Site Manager authentication and limits](https://developer.ui.com/site-manager/v1.0.0/gettingstarted) · [Connector contract](https://developer.ui.com/network/v10.6.106/connectorpost)

| Method | Path on `api.ui.com` | Purpose | Confidence |
|---|---|---|---|
| GET | `/v1/hosts`, `/v1/hosts/{id}`, `/v1/sites`, `/v1/devices` | Account-wide host, site, and device inventory. [Site Manager API](https://developer.ui.com/site-manager/v1.0.0/gettingstarted) · [Implemented operations](https://github.com/enuno/unifi-mcp-server) | High |
| GET, POST | `/v1/isp-metrics/{type}`, `/v1/isp-metrics/{type}/query` respectively | ISP metrics, with aggregation types such as `5m` and `1h`. Metric freshness can lag controller state. [Site Manager implementation](https://github.com/enuno/unifi-mcp-server) · [Observed v1 calls](https://community.ui.com/questions/Site-Manager-ISP-metrics-API-returning-data-30-to-65-minutes-old-across-multiple-gateways/6d145748-d8b2-40a1-948e-7490c39bb41e) | High paths, Medium freshness |
| GET | `/v1/sd-wan-configs`, `/v1/sd-wan-configs/{id}`, `/v1/sd-wan-configs/{id}/status` | Read SD-WAN configurations and deployment state. [Vendor operation](https://developer.ui.com/site-manager/v1.0.0/getsdwanconfigbyid) · [November path reconciliation](https://github.com/enuno/unifi-mcp-server) | High paths |

The reporter verified recovery that day. Treat local reachability as the dependency for private route automation. **Medium.** [Incident and recovery](https://github.com/swkstudios/unifi-fabric-mcp-server/issues/44#issuecomment-3488883721)

## 2. Private API transport, authentication, and limits

`C` and `V` below are the shorthand used in sections 3 and 4. Ports are defaults and can be overridden. **Medium** for the private HTTP behavior. [aiounifi transport](https://github.com/Kane610/aiounifi/blob/master/aiounifi/interfaces/connectivity.py) · [Art of WiFi deployment matrix](https://artofwifi.net/blog/unifi-api-authentication-local-admin-vs-api-key-vs-site-manager) · [Ubiquiti self-hosting guide](https://help.ui.com/hc/en-us/articles/34210126298775-Self-Hosting-UniFi)

| Deployment | Login | `C` classic site base | `V` private v2 site base |
|---|---|---|---|
| UniFi OS console, usually HTTPS `443` | `POST /api/auth/login` | `/proxy/network/api/s/{site}` | `/proxy/network/v2/api/site/{site}` |
| UniFi OS Server, usually HTTPS `11443` | `POST /api/auth/login` | Same proxy path | Same proxy path |
| Standalone self-hosted Network Application, usually HTTPS `8443` | `POST /api/login` | `/api/s/{site}` | `/v2/api/site/{site}`, where implemented |

- **Login and CSRF — Medium.** Send JSON such as `{"username":"network-automation","password":"<secret>","rememberMe":true}`. Some clients use `remember` or send both variants. On OS, capture `Set-Cookie`, normally `TOKEN`, and send applicable cookie pairs on the same origin. Use a response `X-Updated-Csrf-Token` when present, otherwise `X-CSRF-Token`, and update the stored token and cookie as responses rotate them. Some clients can obtain `csrfToken` from the `TOKEN` payload if the header is absent. A build that requires a bootstrap CSRF token can supply it on `GET /` before login. Send the current `X-CSRF-Token` on authenticated writes and preserve cookie/token pairing. Standalone login uses its own session cookie. [aiounifi login](https://github.com/Kane610/aiounifi/blob/master/aiounifi/interfaces/connectivity.py) · [Art of WiFi client transport](https://github.com/Art-of-WiFi/UniFi-API-client/blob/main/src/Client.php) · [UniFi OS bootstrap observation](https://github.com/LayerTM/unifi-unas-ha/blob/main/docs/API.md)
- **Account and MFA — High for the recommendation, Medium for branches.** Create a dedicated **local-only** account with access to the required Network sites. Use a view-only role for reads and the minimum supported write role for mutations. Home Assistant documents local users for its integration. `aiounifi` implements an optional local `ubic_2fa_token` branch and a separate UniFi OS SSO branch using HTTP `499`, `data.mfaCookie`, and a subsequent request with `token`. Those are implementation observations. Use API keys or a dedicated local account for unattended work, and verify local-account availability if the console is enrolled in a Fabric. [Home Assistant setup](https://www.home-assistant.io/integrations/unifi/) · [Ubiquiti MFA](https://help.ui.com/hc/en-us/articles/115012986607-Multi-Factor-Authentication-MFA) · [aiounifi MFA implementation](https://github.com/Kane610/aiounifi/blob/master/aiounifi/interfaces/connectivity.py#L398) · [Art of WiFi authentication matrix](https://artofwifi.net/blog/unifi-api-authentication-local-admin-vs-api-key-vs-site-manager)
- **Expiry and lockout — Medium.** An observed OS expiry hint is `X-Token-Expire-Time`. No portable fixed session lifetime was verified. Reuse the session, serialize re-login, and retry a read once after a genuine `401` or `api.err.LoginRequired`. For login `429`, honor `Retry-After` when provided and back off with jitter. On one OS Server deployment, five failed logins returned `403`, then the sixth returned `429` with `AUTHENTICATION_FAILED_LIMIT_REACHED`. The count and recovery interval are build-specific observations. Pause on repeated bad credentials, `403`, or permission errors instead of cycling login for every poll. [Session observations](https://github.com/kjmagnan1s/unifi-agent/blob/main/docs/API_REFERENCE.md) · [Reproduced lockout](https://github.com/hobbyquaker/unifi2mqtt/issues/23) · [Home Assistant re-login incident](https://github.com/home-assistant/core/issues/163913)
- **TLS and API-key behavior — High for TLS, Medium for private key acceptance.** Trust the console’s configured certificate or a verified CA per controller and keep hostname verification enabled. Apply the trust configuration to HTTP and WebSocket connections. Some OS builds accept local API keys on selected private paths. Treat that as a tested capability of that deployment. The standalone Network Server has no supported key workflow in the client implementations reviewed. [Ubiquiti TLS options](https://help.ui.com/hc/en-us/articles/34210126298775-Self-Hosting-UniFi) · [Node TLS](https://nodejs.org/api/tls.html) · [Art of WiFi transport support](https://github.com/Art-of-WiFi/UniFi-API-client)

## 3. Private endpoints and payloads

A typical classic response is `{"meta":{"rc":"ok"},"data":[...]}`. Read `meta.rc` even on an HTTP success. Private v2 lists can be bare arrays, with some resources and client adapters using a `data` wrapper. An HTTP success with HTML can mean the application is starting or the request reached the login/UI route. The examples below show the relevant fields. A write labeled **mutation fragment** must be applied to the existing writable document where the row calls for a full PUT. [Classic client request handling](https://github.com/Art-of-WiFi/UniFi-API-client/blob/main/src/Client.php) · [aiounifi parsing](https://github.com/Kane610/aiounifi/blob/master/aiounifi/interfaces/connectivity.py) · [Observed HTML response](https://github.com/ruaan-deysel/ha-unifi-insights/blob/main/CHANGELOG.md)

## 4. Policy-Based Routing and Traffic Routes

### Discover WAN and VPN IDs and safely switch egress

1. **Inventory WAN profiles.** Read `GET C/rest/networkconf`, filter `purpose:"wan"`, and record `_id`, `name`, and `wan_networkgroup`. Typical groups are `WAN` and `WAN2`; `WAN1` can be the UI label for `WAN`. The official `GET S/wans` returns identifiers and names for the Integration API. Verify which private `_id` the route actually uses before mapping the two namespaces. **Medium mapping, High official WAN list.** [WAN fixtures](https://github.com/Kane610/aiounifi/blob/master/tests/fixtures.py#L5295) · [Observed WAN mapping](https://darkwolfcave.de/unifi-wan-failover-pendeln/) · [Official WAN list](https://developer.ui.com/network/v11.0.97/getwansoverviewpage)
2. **Inventory outbound VPN clients.** From `C/rest/networkconf`, filter `purpose:"vpn-client"` and retain `_id`, `name`, and VPN type. WireGuard and OpenVPN are supported UniFi client types. Save a route for each candidate WAN or VPN in the UI and compare the returned `/trafficroutes` records. Use the resulting egress `network_id` and accompanying `next_hop` as the mapping, including for WireGuard. Runtime tunnel/interface names may differ from profile IDs. **Medium discovery, Low universal egress crosswalk.** [Client-profile discovery on 10.6](https://github.com/ruaan-deysel/ha-unifi-insights/blob/main/CHANGELOG.md) · [WireGuard client and Traffic Routes](https://help.ui.com/hc/en-us/articles/16357883221015-UniFi-Gateway-WireGuard-VPN-Client)
3. **Apply one desired route per client where qualified.** Read the route under a write lock, update `network_id` and any egress-specific field confirmed by the UI comparison, preserve `kill_switch_enabled` and matching criteria, and PUT the complete object. Read it back and verify **new connections from the selected client** through the expected WAN or VPN. Verify IPv4 and IPv6 when both are enabled. Existing flows and new flows can behave differently, so test both where continuity matters. A single update avoids a coordination gap between multiple competing rule toggles. On a build qualified only for toggles, use UI-created routes with deterministic precedence and test the intermediate states. **Medium recommendation, Low untested platform combinations.** [Full-object update](https://github.com/sirkirby/unifi-mcp/issues/376) · [WAN connection behavior](https://help.ui.com/hc/en-us/articles/360052548713-WAN-Failover-Load-Balancing-and-Port-Remapping-on-UniFi-Gateways) · [PBR fallback and kill switch](https://help.ui.com/hc/en-us/articles/12566175125783-UniFi-Gateway-Policy-Based-Routing)
4. **Schedule by desired state.** For hourly changes, persist the schedule, IANA time zone, and desired egress. Recompute the current desired state after a restart and skip an already-converged route. For privacy-sensitive traffic, treat provisioning and fallback as separate checks: the controller may store the new rule before the gateway enforces it, and the kill switch protects the selected route’s failure behavior while that route applies. Domain matching requires clients to use the gateway as their DNS server. **Medium recommendation, High documented DNS and fallback behavior.** [Policy Engine scheduling](https://help.ui.com/hc/en-us/articles/5546542486551-Traffic-Policy-Management-in-UniFi) · [PBR behavior](https://help.ui.com/hc/en-us/articles/12566175125783-UniFi-Gateway-Policy-Based-Routing) · [Reported controller-to-gateway apply failure](https://community.ui.com/releases/UniFi-Network-Application-11-0-104/f6136744-4cf3-460d-93a6-c5328a89ab22)

**Open-source precedents — Medium.** Home Assistant Core exposes PBR rule switches through `aiounifi`, whose update retains the route document. `ha-unifi-insights` adds outbound VPN client switches and reports live testing on a UDM-SE running 10.6. `sirkirby/unifi-mcp` exposes enable, kill-switch and match-field changes. ## 7. Operational pitfalls and feature design

| Pitfall | Practical handling | Confidence |
|---|---|---|
| **Site and object identifiers** | Persist controller identity plus the private site’s internal `name` and the official site UUID. `default` is a common internal name and can survive a display-name change. Map explicitly using discovery. Keep official UUIDs, legacy `_id`s, MACs and physical port indices distinct. [Official site schema](https://raw.githubusercontent.com/enuno/unifi-mcp-server/main/scripts/scraped-api-spec-v11.0.97.json) · [Multi-site bug and fix](https://github.com/ruaan-deysel/ha-unifi-insights/blob/main/CHANGELOG.md) | High official fields, Medium legacy mapping |
| **Concurrent read-modify-write** | Give each controller/site one mutation queue or shared lease. Fetch immediately before editing and patch the intended fields. Preserve unknown fields and detect external edits with a fingerprint of the writable document. An app lock coordinates the app’s workers; an administrator can still change the same rule in the UI. Conditional-write support for these private resources was unverified. [Full-route update](https://github.com/Kane610/aiounifi/blob/master/aiounifi/models/traffic_route.py#L81) · [Port override field-loss incident](https://github.com/ubiquiti-community/terraform-provider-unifi/issues/430) · [DNSControl sequential writes](https://github.com/DNSControl/dnscontrol/blob/main/documentation/provider/unifi.md) | Medium |
| **PUT semantics** | Use the published request DTO for Integration PUTs. Round-trip the private route, Traffic Rule, ZBF policy and port-forward document for those adapters. For device `port_overrides` and `radio_table`, preserve the full relevant array. Treat sparse `upd/user` and WLAN toggles as endpoint-specific exceptions. Never use a redacted snapshot as a complete restore payload. [Official policy PUT](https://developer.ui.com/network/v11.0.97/updatefirewallpolicy) · [Private policy source](https://github.com/Kane610/aiounifi/blob/master/aiounifi/models/firewall_policy.py#L501) · [Device and WLAN examples](https://github.com/kjmagnan1s/unifi-agent/blob/main/docs/API_REFERENCE.md) · [Secret-aware snapshots](https://github.com/shields/unifi-sync) | High official contract, Medium private behavior |
| **Provisioning and propagation** | Track “accepted by API,” “configuration confirmed by reread,” and “confirmed on the device or data plane” separately. Use bounded polling and an egress test for PBR. On a timeout, inspect current state before retrying. Restart, PoE cycle, voucher creation, and speed tests can have already taken effect. No portable provisioning SLA was verified. [Observed apply failure](https://community.ui.com/releases/UniFi-Network-Application-11-0-104/f6136744-4cf3-460d-93a6-c5328a89ab22) · [Post-write verification precedent](https://github.com/shields/unifi-sync) | Medium |
| **Ordinary-client quotas** | Decide whether the quota measures WAN bytes or all client traffic. Persist interval identity, sample coverage, direction and units. Handle missing buckets and counter resets before enforcing a threshold. Test the chosen enforcement action from a client. For guest-only quotas, use the native voucher or guest authorization limit. [Guest quota support](https://help.ui.com/hc/en-us/articles/31228198640023-External-Hotspot-API-for-Authorization-Clients) · [UniFi statistics semantics](https://github.com/Art-of-WiFi/UniFi-API-client/blob/main/API_REFERENCE.md) | High native scope, Medium app design |
| **New-device approval** | For a true pre-access gate, use a restricted onboarding network with Hotspot authorization, a supported MAC allowlist, or RADIUS/802.1X. A WebSocket-triggered block acts after observation, so it can leave a window of access. Account for randomized MACs. Pending-device adoption in the Integration API concerns UniFi infrastructure. [MAC restriction and hardware limits](https://help.ui.com/hc/en-us/articles/18565355579799-MAC-Address-Restricting) · [External Hotspot flow](https://help.ui.com/hc/en-us/articles/31228198640023-External-Hotspot-API-for-Authorization-Clients) · [Adoption schema](https://opastorello.github.io/unifi-api-docs/network/v11.0.97/index.html) | High native controls, Medium workflow inference |
| **PoE watchdog** | Check native Device Supervisor first. For an app-owned watchdog, require repeated failures, a cooldown, a retry ceiling, and an explicit device-to-port mapping. Verify the target port is PoE-capable and exclude uplinks. Avoid overlapping recovery rules for the same port. Prefer the official `POWER_CYCLE` action. [Native Auto-Recovery controls](https://community.ui.com/releases/375288b9-a4b4-46f1-a19d-5c787d342c2b?parentReplyIds=057b1fda-2960-40c0-ac2c-bc41b4eac955&replyId=98030981-5819-4180-b29d-34a888cc0036) · [Port protection precedent](https://github.com/Hyperion5088/homeassistant-unifi-network-infrastructure/blob/main/docs/entity-attribute-contract.md) · [Official port action schema](https://opastorello.github.io/unifi-api-docs/network/v11.0.97/index.html) | High native feature, Medium app design |
| **Snapshot diffs** | Collect named configuration resources with controller and firmware metadata. Redact PSKs, VPN keys, credentials and voucher codes from review snapshots. Normalize volatile fields and preserve order where it affects behavior, especially firewall ordering. Record partial reads as incomplete snapshots. Keep UniFi’s native backups for recovery. [Native backups](https://help.ui.com/hc/en-us/articles/360008976393-Backups-and-Migration-in-UniFi) · [Secret-aware diff precedent](https://github.com/shields/unifi-sync) · [Firewall ordering](https://developer.ui.com/network/v11.0.97/updatefirewallpolicyordering) | High native backup and ordering, Medium app design |

The main validation gap is **changing a single private route between WAN1, WAN2, and each outbound VPN type across the target fleet**. The full-document toggle has stronger implementation evidence. For interface changes, the release criterion should be a matching read-back **and** a new connection from the intended client exiting on the expected interface. That distinction also applies after upgrades and during VPN failure.
